# Independent report inspection, 7 September 2026

Inspected the committed 0.6.0 public reports before changing implementation. This is an agent walkthrough, not a claim about recruited human participants. The starting point was the user's task: see useful evidence quickly, investigate a model/data question, and share a readable image or printed view.

## Evidence captured before repair

The independent capture covered all seven tabs of all three public reports at 1440 and 390 CSS pixels. Seven regression PDFs covered the selected tab in print. The committed PNGs were viewed at their real dimensions; their full-page sizes ranged from 2160×1500 to 2160×2729. Local before-repair evidence is in `/home/mmazzarelli/.cache/autoxplain-layout-0.6.1/independent-audit/`: `audit.py`, `geometry.json`, the tab PNGs and print PDFs. This cache is supporting inspection output, not a required package dependency. The HTML remained offline, with no refitting or replacement of recorded evidence.

At 1440px, page heights were: Comparison 1067, Selection 1819 (tree), Data 1202 (parcel_kg), Effects 1052, Predictions 1452, Checks 1251, Methods 1112. At 390px, Data was 1744 and Selection 2584. These are observations, not suggested universal pixel budgets.

## Ranked findings

1. **The README gallery is an archive of whole pages, not readable examples.** `validation/capture-screenshots.py` uses `full_page=True` for every tab, including all closed disclosure rows and footer. Model Selection becomes a 2729px-tall image. GitHub scales that into tiny type; the footer and repeated supporting rows consume attention without demonstrating an additional task. The fixed sidebar stops at the capture viewport while the report continues, making the lower page look abandoned. `guided-overview.png` and `model-comparison.png` also duplicate the same capture. Capture a purposeful, honest viewport or bounded component with the relevant controls and evidence; let a nearby link open the complete report. Do not conceal a broken live layout with cropping. Acceptance should inspect the image at actual README display width, not only compare hashes or require full-page screenshots.

2. **Data has a large navigation tax before the first chart and a disclosure tail after it.** In `model-report-390-data.png`, the first chart begins at y=1019, beyond a 900px phone viewport. The header, export status, three controls, repeated population sentence, a 210px column picker, two statistics rows and view buttons all come first. After the desktop chart ends at y≈821, its legend, long static explanation, three separated disclosures and footer add roughly 380px. Main selectors: `.data-controls`, `.data-population`, `.data-column-list`, `.data-summary`, `.data-chart-note`, `.data-values`, `.data-ledger`, `#data-export-details`. A compact mobile column selector and compact context/control grouping can retain every choice while showing evidence sooner. Move binning/export mechanics into contextual help and reduce stacked outer spacing. An acceptance task should change raw/processed values and column on a phone and reach the resulting plot without traversing mostly administrative content; it should still expose missing counts and evaluation overflow.

3. **Selection presents the same candidate list twice and spends too much space on repetitive status.** Seven candidate labels appear beside a chart and again in a full table; five technical disclosures then follow. The three headline cards are identical for the regression example. A compact chart/table toggle or chart-row inspection can preserve exact settings and fold evidence while reducing the default page substantially. The family choice and search rationale must remain immediately accessible. Do not solve this by removing requested hyperparameters. Main selectors: `.selection-decision`, `.selection-rationale`, `.selection-candidate-table`, `.selection-chart-wrap`; generator `R/report_selection.R`. Acceptance must still answer why a worse numerical CV score was chosen and inspect the exact recorded fold values, rather than require the old full table to stay permanently visible.

4. **Predictions gives a six-point residual summary a full-width second row and repeats chart help.** `model-predictions.png` has two useful side-by-side plots, followed by a six-point mean-residual plot spanning almost 1200px. Each chart adds its own 'Reading the chart' and 'Chart values and support' disclosure rows. A compact secondary diagnostic beside the error distribution or a purposeful diagnostic selector would leave room for the actual mistakes. The calibrated 0–1 axes in classification should remain intact even when only two points are present; sparse data alone is not a justification for misleading axis cropping. Main selectors: `.prediction-chart-grid`, `.axr-chart-guidance`, `.axr-chart-values`; `R/report_predictions.R`. Acceptance should compare original values and availability of each diagnostic after reorganizing, not preserve one particular grid.

5. **Checks drops the statistical identity of its own result.** `R/reporting.R::render_performance_uncertainty()` displays generic `quantity/estimate/lower/upper`, the generated caption 'Values: quantity, estimate, lower', and 'primary/baseline/difference'. It does not name the actual models, configured metric or units. A user arriving at Checks cannot tell whether 3.00 means RMSE, MAE or something else. The paragraph also repeats the negative-difference caveat. The disagreement warning asks the user to report model importance ranges without linking to those ranges. Use explicit model/role names, metric/units, interpretable interval columns, and a concrete evidence destination. Do not label an arbitrary supplied reference as an intercept-only baseline. Verify using a nondefault metric and custom reference model, not only the public RMSE example.

6. **Print leaves isolated content and empty headings.** Checks creates a second page containing only the one-row parcel_kg missingness table and caveat. Predictions ends page 1 with the orphan heading 'Does error change with the prediction?', followed by its small plot alone on page 2. Selection's first page has the rationale but no plot, while the second contains the whole repeated plot/table. Methods prints 'Retained model specifications' but hides all closed model specification summaries below it. PDFs: `model-report-{checks,evaluation,selection,provenance}-print.pdf`. Content-aware print density should keep a chart title with its marks and a table caption with its rows, retain relevant model summaries, and avoid new pages for one short row when ordinary spacing can fit it. Do not shrink type indiscriminately or suppress evidence to satisfy page count.

7. **Existing validation can approve all of this.** The gallery smoke test checks selected panel count, document horizontal overflow and interaction state. It never asks where the first chart begins, whether the whole capture remains readable at GitHub width, whether the image has an administrative tail, or whether a printed page contains only an orphan row. The manifest proves assets match source; it does not prove useful composition. Add a few user-task acceptance constraints and deliberate negative controls (excessive bottom padding, restored bulky mobile picker, orphan print title) while retaining numerical and keyboard tests. Avoid a proliferation of exact-markup assertions that freeze the present design.

## What should be preserved

The current Data distributions show the actual raw/processed split, missing counts and overflow; the controls work without a backend. Model settings are now available directly. Selection includes actual candidate/fold evidence. Predictions retain source-record links and cutoff semantics. These are useful capabilities. The remaining work is to give them an intelligible hierarchy and remove the repeated framing that delays reaching them.

## Checks repair verified during this audit

The interval table now names the recorded metric and units, the actual primary and reference model, and the confidence level. It keeps the original estimates and endpoints even when the input rows are reordered. Method assumptions remain available through one disclosure; small-sample, degenerate-bootstrap and reused-evaluation cautions remain visible. The missingness table also has a descriptive caption.

The importance-disagreement action now opens the already-recorded near-optimal candidates' importance ranges. That table identifies the candidates and metric, and explains that the ranges are neither confidence intervals nor bounds over all models. No new inferential procedure was added.

Five tests in `tests/testthat/test-checks-statistical-identity.R` cover a custom reference, escaped names, a nondefault metric, reordered numerical rows, classification units, grouped sampling cautions, actual range values and absence of dead links when no comparison exists. They also verify that missingness changing from 20% to 30% is displayed as +10.0 percentage points. A second independent reviewer caught an ambiguous importance caption: positive importance denotes a score decrease for accuracy and AUC, but a loss increase for MAE and RMSE. Two actual explainer audits verify that convention against the recorded shuffled scores, and the captions now state the direction. The final test uses a real failed additive-model fit to check the failure warning's link against the recorded configuration and error. All 58 assertions passed; the existing report-uncertainty and release-workflow tests passed another 86 assertions. Five identity checks failed against the untouched 0.6.0 renderer and passed against the repair. An offline browser check at 1440 and 390px followed the warning to its visible five-row evidence table and checked the actual 2.3048 range endpoint.

Other layout changes identified above are being handled separately; this audit's initial measurements are not acceptance measurements for the final package.

## Findings from the first re-review

The first revised mobile Data view reached its chart at about 608px instead of 1019px, and the three regression prediction diagnostics were readable together on desktop. Methods retained all four model summaries in print. Those improvements did not make the print work complete.

The first version of the layout gate counted PDF text lines when looking for short leftover pages. That was a poor criterion: Poppler counted separate table cells as separate lines, allowing a nearly empty page to pass. Reviewing the PDF exposed the mistake. The guard now measures the vertical extent of the printed text and retains the PDF for inspection. This rejected the regression Checks page containing only one small table and its caveat. A subsequent layout improvement fit the table, but still left its two-line caveat alone on the next page; the same guard rejected that version too.

Moving the distribution explanation into contextual help also introduced a print regression. The explanation was present in the DOM but clipped at the right page edge. Checking its complete text in the actual PDF rejected all three affected Data reports. These findings demonstrate why element presence, a source manifest, or a successful render are not sufficient acceptance evidence.

The next PDF review found importance values extending past the right border of the binary Features panel. The fixed-width numeric column did not fit its longer decimal values. Shared print grid tracks now reserve the widest actual value while keeping a common bar scale across features. A new print-media text-range check at A4's printable width rejected overflowing values in all three untouched 0.6.0 reports, including the binary values that first exposed the defect. An intentionally displaced endpoint also fails the same check.

The multiclass Checks warning also sent a reader out to an R expression despite retaining the fold errors in the report. It now names the actual model family and links to that family's first failed configuration; Selection changes family, opens the fold record and focuses its summary. The precise R expression remains in an optional disclosure. An older saved run without the corresponding Selection evidence keeps its original recommendation rather than acquiring a dead link.

One new caption check initially rejected a valid wrapped binary ALE title because Poppler interleaved text from the neighboring importance panel. The corrected check reconstructs adjacent lines within the same column and requires the exact caption. It does not accept scattered title words from axes or guidance. The deliberately orphaned PDF continues to fail after this correction.

Following the new warning link exposed another problem that a successful click did not settle: the phone fold table squeezed its long Error column into very tall rows. A first width adjustment still left 155px rows. The final screen-only rule gives the last text column enough room for a short paragraph, capped to fit the phone's horizontal scroll viewport. The actual error rows are 97px high at 320px and 77.5px at 390px; their complete text remains reachable. Numeric fold values, configuration identities and print sizing are unchanged. The gate checks both readable text width and row shape, and rejects an intentionally crushed Error column.

## Acceptance of the reviewed reports

The final independent run of `validation/check-layout-tasks.py` passed **128 checks with no browser errors** against reports regenerated from the three saved fitted cases and the final source. It captured all seven tabs at 1440 and 390px and produced 21 selected-tab PDFs. The actual CV-failure warning was followed from Checks to its focused, open fold record at both widths. Additional 320px and 390px viewport inspection confirmed the complete horizontally scrolled error column. Evidence is in `independent-audit/final-layout/` beneath the cache directory above; `layout-task-checks.json` records the input HTML hashes and browser version, and `fold-errors-{320,390}.png` records the additional narrow views.

The Data chart starts at about 407px on desktop, 608px on the regression and binary phones, and 590px on the multiclass phone. The dynamic binning and denominator note prints in full. The regression Checks table, interval assumptions, missingness rows and caveat now fit together on one readable printed page. Methods retains each closed model summary in print. The regression residual title stays with its chart and interpretation. Importance endpoints fit their printed rows, with a common bar scale. These conclusions were checked against the actual PDFs and screenshots, not just element presence.

The same final gate rejects **11 real defects in the untouched 0.6.0 HTML**, with no browser errors: three late mobile Data charts, three missing sets of printed model summaries, three overflowing importance panels, an orphan residual title, and a nearly empty Checks continuation page. Separate deliberate mutations fail for excessive setup spacing, a printed orphan title, displaced importance values and a crushed fold-error column. These controls establish that the checks distinguish the defects from the repairs; they do not make the checks a complete assessment of design quality.

The gate is included in `.github/workflows/report-browser.yaml`, with its screenshots, PDFs and JSON covered by the existing evidence upload. This review covers the three public examples and the specific tasks above. It does not establish usability for every possible dataset or replace the package's numerical, accessibility and interaction checks. The image capture and gallery work are reviewed separately; these inspection screenshots intentionally retain full-page context and are not the README gallery assets.
