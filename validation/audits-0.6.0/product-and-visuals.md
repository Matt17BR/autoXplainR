# Independent post-0.5.0 product / visual audit

Read-only inspection of all six public tabs, regression/binary/multiclass reports, at 1440, 1200 and 390 CSS pixels in isolated Chrome. Evidence: `inventory.json`, full-page PNGs named `{task}-{width}-{tab}.png`, `interactions.json`, `link-check.json`. No participant study or WCAG conformance assessment. The binary Checks axe scan had no violations and an unresolved color-contrast manual check. Mechanical success is distinguished from usefulness below.

1. **P1 — The opening answers the wrong comparison.** `R/report_explorer.R:153–213` says which retained model has the best test number, gives all three cost columns, and allocates roughly half the area to costs. Delivery's 2.997 versus 3.007 RMSE needs a baseline delta and a statement about absent evaluation-sample uncertainty, not a scatter that visually separates 1 versus 6 milliseconds. Churn's 48-row caveat is hidden in Checks while the opening promotes a winner. Preserve training-selected identity; show primary score, baseline difference, sample scope and leading limitation, then a compact candidate table with comparable uncertainty. Cost is a secondary view.

2. **P1 — The cost graphic makes tiny operational differences look decisive.** `R/reporting.R:539–611` takes min/max ranges with no padding, reverses loss vertically, uses numbered labels and a key. `R/model_tradeoffs.R:80` reorders models for each pair of axes, so point 2 changes from Neural to Tree when changing fit to prediction time. The exact source numbers are correct; their hierarchy and identification are poor. At1200 the comparison page grows from1004 to1518px because `explorer.css:953` stacks the chart. Direct labels, padded domains, stable model identities, a short explicit measurement-scope line, sensible precision, and a compact height should replace the large key-driven graphic. Do not imply timing rank is stable without repetitions.

3. **P1 — Control changes discard a reader's question.** `explorer.js:149–150` binds resource selection to chooseMetrics, which always sorts by score at89. Reproduced Fit sort `[main,baseline,neural,tree]` becoming score sort `[main,neural,tree,baseline]` after only selecting model size. Model/feature/class state is absent from the URL; reload of Neural/months returns Main/support_calls. Preserve the compatible feature across model changes, keep independent sort/metric/resource state, and provide shareable/reloadable state. Events must distinguish view changes from model selection.

4. **P1 — Scope changes silently between Predictions and Checks.** Inspect Neural in the binary report:12/48 errors. Then Checks presents an unlabeled 'The model' cutoff table whose0.5 row is3FP+8FN=11 (the primary model). `report_explorer.R:709` calls the primary-only threshold renderer (`reporting.R:900`) outside model panels. Every diagnostic needs visible model/event/data scope; selected-model checks must actually follow the selection or state that they are primary-only.

5. **P1 — Affected-evidence navigation does not land on evidence.** The neural/months warning links to a raw feature table under Methods (`reporting.R:1489,1532`), not the relevant feature workspace. Once hashchange settles, the Methods tab opens atscrollY0, focus H2; the target row is at y1321 in a900px viewport. `explorer.js:35–62` explicitly scrolls every fragment navigation to the top. Dispatch model+feature selection and focus/scroll the actual evidence; retain a separate raw-values link.

6. **P1 — Features support looking at one curve, not comparing behavior.** `report_explorer.R:337–406` presents only the model's top inputs, independently ordered and scaled. A different selected model can move to a different feature, so viewers must memorize a curve and its axes. Importance is rendered as crisp bars with uncertainty hidden (`216–255`); the headline's first-to-last change (`318–329`) implies a simple trend even for U shapes and ordered categories. Offer one searchable shared feature list, primary/comparator overlays on common units/domains, a visible interval/status cue for shuffle results, and descriptions that do not infer trend from endpoints. A feature absent from the explanation budget needs a distinct computed/not-computed state, not disappearance.

7. **P1 — Support marks are technically present but not interpretable enough.** `reporting.R:1262–1279` draws 20px relative-support marks labeled0–1, without count ticks, bin boundaries or a meaning for that relative scale. The quantile grid makes almost equal marks look like uniform data support despite unequal interval widths. Effect axes do not themselves name target units/event; those are elsewhere. Use aligned support bins with actual counts and a clear denominator, selected-bin details, explicit target/probability units, and table equivalents. Categorical effects should be horizontal category/value plots: the390px service chart is600px wide inside332px and shows only economy, hiding priority with no visible scroll instruction.

8. **P1 — Input relationships is a dead end and its mobile repair is worse than scrolling.** `report_explorer.R:444–529` shows only first12 inputs, duplicates both matrix triangles plus diagonal, mixes signed correlations and unsigned statistics in one color ramp, and a click reveals a sentence already in the accessible label. There is no distribution, scatter, target relationship, missingness comparison, filter or route back to a feature. At390 the regression row-label cells are34px wide: planned_route_hours becomes a242.6px tall near-vertical word; the matrix page is1613px. Replace the isolated matrix with a Data workspace: searchable columns, raw/processed/partition scope, distribution, selected pair visualization and exact method/sample counts. Keep a matrix as an optional overview with real minimum label width and explicit scrolling. On phones use a sortable pair list, not a squeezed matrix.

9. **P1 — Prediction inspection omits the actual investigation.** Regression uses a very large observed/predicted graphic (`664–695`) with pointer-only native circle titles and just the10 largest errors in an equivalent table.72 points are shown in the public fixture but zero points have keyboard focus;62 observations cannot be recovered through the table. There is no row feature context or error filter. Classification's huge uncolored table (`598–617`) hides mistakes/calibration, lacks normalized rates and per-class comparisons, and is disconnected from cutoffs. A compact plot beside a linked error table, explicit row-export mode, selection detail with inputs/observed/predicted, and class/threshold/calibration controls would answer the task. Show distribution/aggregate alternatives when rows are not exported; summary mode must not hide raw rows only visually.

10. **P2 — Methods & export is mostly a file cabinet of developer commands.** `report_explorer.R:734–756` fronts four R expressions but no actual export control, scope manifest, saved selection or downloadable visible data. Model details, settings, metadata and duplicate feature tables are buried in similar disclosures; metric definitions are nested twice. A methods ledger should expose data/evaluation/selection provenance, retained warnings and engine versions, with an export panel naming exactly what HTML/PDF/table outputs include. 'Print this view' is a legitimate narrow action, but closed detail content is omitted (`explorer.css:798–805`) and help disappears in print; printed charts need their own units, limitations and selection scope, not reliance on a hidden tooltip.

11. **P2 — The shell is generic and needlessly consumes the first screen.** Dark224px sidebar, repeated section numbers, a140px report heading and repeated model identity/settings create visual bulk without analytical content. At390 the first effect chart starts around y1097. The issue is not the green palette itself; it is a generic application frame wrapped around sparse static evidence. Use one restrained identity strip, shorter task navigation, compact control toolbar and task-specific pane layouts. Avoid repeating 'keep the analysis usable', 'what needs a closer look' and heading-number-brand scaffolding. Space should support labels and comparisons, not create height around four measurements.

12. **P1 — The visual tests systematically miss these failures.** `validation/check-explorer.py:35–48` collects overflow elements but pass/fail only uses page count/document width; clipped SVG text and pathological wrapping pass. The390px model-size x-axis label has boundingbox x=-7.48 to397.48 and is visibly clipped although document width390. Tests compare raw SVG user coordinates against R numbers (`report_geometry.py`) before responsive viewport loops, not effective screen boxes. Responsive loops test a limited current selection, missing the categorical service and alternate resource cases. PNG capture is not a visual assertion. Current fixtures have only3–5 predictors and4 models. Keep numerical oracles, but add task-state tests, actual rendered label/clipping/row-height checks, long-label/high-dimensional/constant/near-tie fixtures, and human review at actual size. Include a deliberately bad visual mutation for every claimed gate. No pass count substitutes for reading the report.

## Coherent component plan

- A compact identity header: analysis title, outcome/event, primary model, evaluation partition/rows. One scope strip names the leading caveat. Navigation: Compare, Data, Features, Predictions, Selection, Checks, Methods (only tabs with substantial workspaces).
- Compare: a model table whose rows include score, baseline difference and interval status; a compact model-score comparison next to it where space permits. Costs become a labeled secondary subview or small panel, with stable direct identification, real axes and a visible measurement limitation.
- Features: one model/comparator/class toolbar, shared feature picker, importance values/intervals and a common-scale effect canvas; aligned support and the exact selected evidence immediately under it. On phones picker first, current curve second, ranked inputs in expandable panel.
- Data: column list+profile workspace, raw/processed and train/evaluation controls, distribution and missingness, pair plot+method/count; matrix optional. Row browser only in explicit row mode.
- Predictions: compact residual/observed plot or confusion rates, linked investigation table and selected-row drawer when exported; classification cutoffs and calibration bound to the same selected model/event. Aggregate-only export uses aggregates throughout the payload.
- Selection: candidate/fold plots and table, selection threshold/rule, actual search ranges/rationale, convergence and failures, retained-fit details. Keep training search separate from displayed evaluation rankings.
- Checks: scope-filtered findings/status ledger with concrete affected-evidence routes; not a collection of unlabeled primary-model calculations.
- Methods: reproducible run ledger and actual export actions with explicit data/view scope.

## What earlier audits should not have endorsed

The numbered scatter key fixed overlap but introduced lookup work and unstable point identity. Fixed minimum widths protected tick size but hid entire categorical answers on phones. Replacing detail with collapsed sections reduced scroll length but concealed uncertainty and essential scope. Presence of numeric axes and no page overflow proved only bounded technical properties; accepting those as evidence of a usable product was mistaken. Preserve the corrected statistics and evidence identities, but judge the next release by whether readers can complete the named investigations.
